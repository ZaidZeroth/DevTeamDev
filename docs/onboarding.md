# New staff onboarding

Use this checklist when a new role joins Enchained Games Bitcoin Studio.

## 1. Establish the role

- Create a private role folder and an `AGENTS.md` for the agent.
- Identify the agent by emoji immediately followed by its name, and state its role, expertise, scope, and escalation path.
- Record its access boundaries, decision limits, protected guarantees, and the public communication route.
- Keep the full ARG and private operating details in the private role folder.

## 2. Learn and document the work

- Read this repository's `README.md`, `AGENTS.md`, and [`team-workflow.md`](team-workflow.md).
- Research a small set of credible sources that directly support the role's objectives.
- Save permitted source material or an attributed private summary with stable links and the date reviewed.
- Add practical, role-relevant learning points to the private ARG without weakening existing guarantees.

## 3. Join the public team conversation

- Review current issues and discussions. Decide which are relevant to the role and contribute only when there is a useful question, answer, or perspective.
- Open a separate top-level introduction issue. Use a speaker-first title in the form `EMOJIName: Introduction — Role` and include a public-safe role and expertise summary.
- Do not post the private ARG, private research notes, personal data, or sensitive details.
- Prepare any public GitHub message or action as a signed request through the approved broadcast workflow. State the exact target repository as `owner/repo` and include the complete proposed content.
- Only Broadcaster may publish. Approval after full screening authorizes only the exact screened publication on the named repository, without a separate owner approval step. Reject unclear or unsafe requests with clear resubmission guidance; do not leave them pending. A clarified resubmission must be a new immutable request linked to the earlier request. Approval does not authorize weakening a prime directive or protected role guarantee; that requires explicit studio-owner permission.

## 4. Maintain and improve the role

- Keep the private ARG and work schedule aligned with the role's responsibilities and boundaries.
- Review useful role-relevant issues on the agreed cadence and track follow-up owners.
- Discuss proposed material ARG changes with the role owner. Changes that could weaken protected guarantees require explicit studio-owner permission.
- Share a public-safe completion summary only through the approved broadcast workflow.
